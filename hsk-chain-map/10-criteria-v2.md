# 10. 평가 기준 v2 (확정 2026-11-24)

작성 2026-11-24 · 인계문 2절의 기준, 해커톤 공고 원문, 이번 대화에서 사용자가 정한 원칙을 합쳤다.

## 0. 후보를 한 문장으로 적는다
> [사용자]가 [상황]에서 [목표]를 이루려면 [결정]을 내려야 한다. 지금은 [기존 방법]을 쓰고, [조건]에서 [비용·실패·추가 개입]이 생긴다. 우리는 [사용자가 정한 기준]에 따라 [한 가지 행동]을 [어떻게] 바꾼다.

**이번에 바뀐 부분:** 문장에 "사용자가 정한 기준"이 들어간다. 자동화만으로는 통과하지 않는다.

## 1. 필수 관문 (하나라도 실패하면 탈락)

| 관문 | 통과 조건 | 근거 |
| --- | --- | --- |
| **G1. Track 1** | 네 가지를 모두 만족한다. ① 온체인에서 거래가 실행된다 ② DEX 같은 거래 장소가 기반이다 ③ AI가 신호를 보고 스스로 매매한다 ④ 메인넷 계약이 기능을 맡는다 | 공고 원문 |
| **G2. 메인넷 시연** | 12/3까지 HSK 메인넷에서 실제 자산으로 소액 작동을 보여 줄 수 있다. 필요한 자산·시장이 체인에 있거나 우리가 만들 수 있다 | 공고: 미배포 시 데모 제외 |
| **G3. 타겟 사용자의 실재** | 그 결정을 실제로 내리는 사람이 **주소나 거래 기록으로 최소 1명** 확인된다. 이 체인이 아니어도 된다. 다만 출처를 밝힌다 | 사용자 원칙: 타겟이 분명하면 살린다 |

**관문이 아닌 것:** 시장 크기, 메인넷 수익. 시장 크기는 발표에서 숨기지 않고 정직하게 다룬다.

## 2. 점수 기준 (위에서부터 중요)

| 순서 | 기준 | 높은 점수 | 낮은 점수 |
| --- | --- | --- | --- |
| S1 | **타겟 명확성** | 누가, 어떤 상황에서, 어떤 결정을, 언제까지 내리는지가 기록으로 확인됨 | 추측 |
| S2 | **페인 또는 위험의 크기 (실제 돈 기준)** | 손실·지연·추가 개입, **또는 결과가 흔들리는 위험(가격 노출)**이 금액·비율로 측정되고 분모가 있음. 위험은 "평균 이익"이 아니라 "나쁜 경우의 손실"로 잰다 | 이벤트 자금, 모의 실험만 있음 |
| S3 | **기존 방법 대비 남는 것** | 사용자가 지금 방법으로는 못 하는 것이 구체적임 | 사용자가 이미 직접 잘하고 있음, 경쟁 봇이 이미 있음 |
| S4 | **사용자 기준 반영** | 사용자가 자기 기준을 정한다. 에이전트는 그 기준으로 결정하고, 근거를 남기고, 기준이 부딪히면 묻고, 결과와 비교해 수정을 제안한다. 돈과 관련된 기준은 계약이 강제한다 | 개발자가 정한 고정 규칙 실행 |
| S5 | **AI의 역할** | 규칙으로 대체하기 어려운 판단(해석, 상충 조정)을 맡음 | 이동평균 같은 규칙과 같음 |
| S6 | **HSK 체인 적합성** | HSKSwap, HSK 자산, KYC(보조) 같은 이 체인의 요소가 행동을 바꿈 | 다른 체인에서도 똑같음 |
| S7 | **해커톤 심사 기준** | 완성도·기술적 성숙도·혁신성을 데모로 보여 줄 수 있음 | |

## 3. 근거를 적는 규칙
- 확인한 것 / 간접 근거 / 확인 못 한 것을 나눈다.
- 블록 번호, 주소, 조회 방법을 적는다.
- **사람 수, 자기 돈, 플랫폼 돈을 구분한다.** 이벤트 자금은 페인 근거로 쓰지 않는다.
- 서로 다른 사람의 사례를 합쳐 한 사람의 흐름으로 만들지 않는다.
- 탈락 사유는 G1~G3 중 무엇인지, 또는 S 기준 중 무엇이 약한지로만 적는다. "작아서"는 쓰지 않는다.

## 4. 판정
- **유지:** G1~G3를 통과하고, S1~S4가 모두 기록으로 뒷받침된다.
- **조건부:** G1~G3를 통과했지만 S1~S4 중 하나가 미확인이다. 무엇을 확인하면 유지가 되는지 적는다.
- **탈락:** G1~G3 중 하나라도 실패한다.

---

> **확정 시 추가 (사용자 의견):** S2에 "위험의 크기"를 넣었다. 헤지처럼 이익을 늘리는 것이 아니라 결과를 안정시키는 제품은 위험으로 평가한다.

## 시험 적용: 기존 "현물·숏 + 분할 매도"는 이 기준에 맞나

| 기준 | 판정 | 근거 |
| --- | --- | --- |
| G1 Track 1 | **통과 (조건 있음)** | 현물 매도는 HSKSwap에서 체인 위로 실행되고, 위임 금고 계약이 한도를 강제한다. 숏은 체인 밖 거래소에서 하므로 "온체인 실행"은 현물 쪽만 해당한다 |
| G2 메인넷 시연 | **통과 (WBTC·WETH만)** | HSK는 숏을 잡을 곳이 없다(Hyperliquid·Bitget·OKX 없음, Gate 폐지 진행, KuCoin 종료). WBTC·WETH는 숏이 가능하고 HSKSwap 풀이 있다 |
| G3 타겟 실재 | **통과** | `0xa40a12D0c47c9B7D91ca0C93E900892C3B45F000`: Hyperliquid에서 숏을 먼저 걸고 현물을 나눠 팔며 숏을 같은 만큼 줄였다(10/1 이후 TREAD 108번 반입). 같은 주소가 HSKSwap에서 WBTC를 147번 팔았다(23,718달러) |
| S1 타겟 명확성 | 중 | 행동은 확인됐다. 다만 **HSKSwap에서 WBTC를 팔 때는 숏을 잡지 않았다**(11/15 0.00017 BTC 시험 거래뿐). HSK 체인에서 이 결정을 내리는 사람은 아직 확인하지 못했다 |
| S2 페인 깊이 | **약** | 한 번에 잡을 수 있는 이익이 약 31달러였다. 판매자들은 이미 풀이 비쌀 때만 골라 판다(50달러 이상 매도 148건 중 시간대 저가보다 싸게 판 것은 1건) |
| S3 기존 방법 대비 | **약** | 같은 사용자가 Hyperliquid에서는 **이미 봇으로 자동화**해 쓰고 있다 |
| S4 사용자 기준 반영 | 설계 가능 | 순노출 범위, 성향, 최저 수령액, 회당 한도를 사용자가 정하는 구조가 이미 있다. "근거 기록, 충돌 시 질문, 결과 비교 후 수정 제안"을 더하면 된다 |
| S5 AI 역할 | 중 | 모의 실험에서 단순 규칙과 모델이 모두 94건 중 87건을 맞혔다 |
| S6 체인 적합성 | 중 | HSKSwap 풀이 외부 가격을 몇 시간씩 늦게 따라간다(WBTC 8.83시간)는 점을 실행 순서에 쓴다 |

**판정: 조건부 (탈락 아님).** 관문 세 개는 통과한다.
- 예전에 이 후보를 접은 이유 중 "WBTC 시장이 0.81 BTC뿐"은 시장 크기 문제라 새 기준에서는 탈락 사유가 아니다.
- 남는 약점은 두 가지다. **S2**(얻는 이익이 작다)와 **S3**(타겟이 이미 다른 곳에서 봇으로 하고 있다).
- 유지로 올리려면 "사용자 기준 반영(S4)"이 기존 봇이 못 하는 것을 준다는 점을 보여야 한다. 예: 사용자가 정한 순노출 범위와 소식에 대한 태도를 지키고, 기준과 결과를 비교해 수정을 제안하는 것이다.
