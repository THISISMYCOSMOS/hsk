# 6. 후보 A(예측시장 거래 에이전트) 점검: Track 1 조건과 결정적 반대 근거

작성 2026-11-24

## 결론 먼저

**A는 "이 체인 사용자가 실제 돈을 잃는다"는 근거로는 쓸 수 없다.**

| 새로 확인한 것 | 근거 |
| --- | --- |
| 예측시장의 HSK는 **플랫폼이 나눠 준 이벤트용 자금**이다 | 활동 계정 120개 표본에서 외부 입금 0건. 모든 입금이 Treasury에서 왔다. 하위 계정 6만 41개의 잔액 합 53.8만 HSK는 자금 흐름 계산 결과(Treasury 지급 721.9만 + 정산 4,454.2만 − 베팅 회수 5,119.9만 = 56.3만)와 맞는다. 일부 조회가 실패해 차이가 조금 있다 |
| **이번 이벤트에서는 HSK를 꺼낼 수 없다** | `SubAccount.sol` 주석: "提现:只能回到 userWallet … **本期活动不启用(HSK 不可提现)**, 保留接口供后续真实资产场景" (이번 이벤트에서는 출금을 켜지 않았고, 나중에 실제 자산을 쓸 때를 위해 기능만 남겨 둠) |
| **사용자 지갑은 하위 계정을 직접 움직일 수 없다** | 같은 파일: "平台 admin 管进出, **用户 EOA 无任何入口**" (돈의 출입은 플랫폼 관리자가 하고, 사용자 지갑에는 아무 입구가 없음). 사용자 지갑 30개 표본 모두 nonce 0 |
| 서비스는 "이벤트(活动)"다 | 하위 계정 생성은 "活动服务"(이벤트 서비스) 역할만 할 수 있다. salt는 `"HSK_PREDICT_SUBACCOUNT"`. 플랫폼 준비금 990.1만 HSK를 `0x6c3d…0283`이 넣었다 |

따라서 04 문서의 "테이커 −270만 HSK, 마감 직전 −99%"는 **실제 돈의 손실이 아니라 이벤트용 자금 안에서의 행동**이다. 판단을 바꾸는 근거는 이 한 가지다. 다만 행동 패턴 자체(마감 직전에 "거의 확실해 보이는 쪽"을 비싸게 사서 진다)는 여전히 사실이다.

## Track 1에 맞추려면 필요한 조건

| 조건 | 지금 A의 상태 | 맞추는 방법 |
| --- | --- | --- |
| ① 에이전트가 **스스로 주문을 낸다** | **불가.** 사용자 지갑에 입구가 없고 외부 API도 확인되지 않았다 | 이 플랫폼에서는 안 된다. **우리가 HSK 메인넷에 예측시장을 직접 배포**하고 그 위에서 에이전트가 거래해야 한다 |
| ② **DEX 기반** | 체결은 체인 밖, 확인은 체인 위인 주문장 | 우리 시장을 **AMM형(풀에서 바로 사고팔기)**으로 만들면 그 자체가 DEX가 된다. 정산 자산을 HSK로 두면 HSKSwap(HSK↔USDT)과 연결된다 |
| ③ 매매 신호 | 결과 확률 추정과 시장 가격의 차이 | 그대로 쓴다. 기초자산 가격(예: 주가, BTC)으로 확률을 추정한다 |
| ④ 메인넷 계약의 역할 | | 시장 계약, 에이전트 한도 금고. KYC는 등급별 한도로만 보조로 붙인다 |
| ⑤ **실제 돈의 페인** | **없음** (이벤트 자금, 출금 불가) | **실제 돈이 오가는 예측시장의 데이터로 증명**해야 한다. 예: Polymarket은 공개 체인에서 정산된다. HSK 데이터는 "같은 행동이 이 체인 사용자에게도 나타난다"는 보조 근거로만 쓴다 |

## 판정
- **A(이 플랫폼 사용자 대상): 제외.** 실제 돈의 손실이 없고, 에이전트가 들어갈 입구도 없다.
- **A′(HSK 메인넷에 AMM형 예측시장 + 거래 에이전트): 조건부.** Track 조건 ①~④는 설계로 맞출 수 있다. ⑤는 Polymarket 같은 실제 돈의 시장에서 "마감 직전 테이커 손실"이 재현되는지 한 번 재 보면 판정할 수 있다. 재현되지 않으면 A′도 보류다.
- **이 체인에서 실제 돈이 오가는 개인 거래의 페인은 사실상 측정되지 않는다.** DEX는 사람 72명, 7개월 4,949달러였고, 예측시장은 이벤트 자금이다. 이 점은 어느 후보로 가든 발표에서 정직하게 다뤄야 한다.
