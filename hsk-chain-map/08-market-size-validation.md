# 8. "시장이 작아서 버린다"는 판단의 검증

작성 2026-11-24

## 결론 먼저
1. **HashKey Chain이 작은 것은 사실이다.** 다만 비슷한 단계의 L2와 같은 규모대다. HSK만의 특수한 문제가 아니다.
2. **지금까지 후보를 버린 이유를 다시 보니 "작아서"가 아니었다.** 대부분 "타겟 사용자가 없어서" 또는 "이미 같은 일을 하는 봇이 있어서"였다. 이 둘은 시장 크기와 다른 문제다.
3. **해커톤 심사 기준(완성도·기술적 성숙도·혁신성)에는 시장 크기가 없다.** 지난 HashKey 해커톤 수상작도 체인 위 시장이 거의 없는 분야에서 나왔다.
4. 그래서 시장 크기는 **두 가지에만** 영향을 준다고 보고 이것만 확인한다. (a) 메인넷에서 실제로 작동을 보여 줄 수 있는가, (b) "누가 쓰나"라는 질문에 데이터로 답할 수 있는가.

**정리.** "작아서" 버린 것처럼 말했지만, 실제로는 대부분 **타겟 사용자 없음, 이미 있는 경쟁자, 트랙 불일치**였다. 앞으로는 이 셋을 시장 크기와 구분해서 적는다.

## 3. 해커톤에서 시장 크기가 문제가 되는 경우

| 질문 | 시장이 작을 때의 위험 | 대응 |
| --- | --- | --- |
| 메인넷에서 작동을 보여 줄 수 있나 | 거래 상대·유동성이 없어 시연이 안 될 수 있다 | 시연에 필요한 시장(풀·예측시장)을 우리가 배포하거나 소액으로 직접 만든다 |
| "누가 쓰나"에 답할 수 있나 | 사용자 데이터가 없으면 답이 약하다 | **이 체인 데이터로 사람과 행동을 보이고**(예측시장 43,313명), 실제 돈의 페인은 더 큰 시장(Polymarket) 데이터로 보강한다 |
| 심사 기준 | 완성도·기술적 성숙도·혁신성. 시장 크기는 없다 | |
| 지난 수상작 | Horizon 본대회: Sentinel Treasury(AI), AssetFlow(RWA) 등. 체인 위 시장이 거의 없는 분야에서 수상 | 시장 크기보다 "생태계에 필요한 것을 완성도 있게 만들었나"를 본 것으로 판단(간접 근거) |

## 4. 판정 규칙 (앞으로 적용)
- **시장 크기만으로는 탈락시키지 않는다.**
- 탈락 사유는 세 가지로만 적는다. (1) 타겟 사용자가 데이터로 보이지 않음, (2) 같은 일을 이미 잘하는 기존 방법·경쟁자가 있음, (3) Track 1이나 메인넷 시연이 불가능함.
- 시장이 작다는 사실은 발표에서 숨기지 않는다. 대신 "작은 시장에서도 사람과 행동이 보인다"는 데이터와 "실제 돈의 시장에서 같은 문제가 크다"는 데이터를 함께 낸다.
