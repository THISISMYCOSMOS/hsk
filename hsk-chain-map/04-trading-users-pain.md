# 4. HSK Chain에서 실제로 "거래"하는 사람은 누구이고, 얼마나 잃고 있나

작성 2026-11-24 · 예측시장 기준 블록 30566896 (2026-11-23 23:40 UTC 전후), DEX 기준 블록 30553002 · 조회는 RPC `eth_getLogs`, Blockscout API v2

## 결론 먼저

- **이 체인에서 가장 큰 거래 사용자 집단은 DEX가 아니라 예측시장이다.**
  - 예측시장은 2026-08-26 이후 하위 계정 **64,291개**, 체결 **359,725건**, 직접 산 사람(테이커) **33,002명**, 테이커가 낸 금액 **2,952만 HSK(약 240만 달러)**다.
  - HSKSwap에서 사람으로 보이는 지갑은 7개월 동안 **72개**, 거래액 **4,949달러**뿐이다.
- 앞에서 쓴 "주간 활동 계정 100개"는 예측시장 사용자를 놓친 숫자다. 사용자 지갑은 직접 거래를 보내지 않는다(표본 30개 모두 nonce 0). 플랫폼이 하위 계정으로 대신 처리한다.
- **페인은 크고 넓게 퍼져 있다.** 테이커 전체는 낸 돈의 **9.2%를 잃었고**(−270만 HSK), 주문을 걸어 둔 쪽(메이커)이 그만큼 벌었다(+20.7%). 손실은 **마감 직전에 몰린다.** 마감 24시간 안에 산 테이커 **22,751명**이 **351만 HSK**를 잃었다.

## 3. 누가 얼마나 잃나

정산된 체결 357,401건으로 계산했다. 승패는 `EventWinners`와 `ComplementRegistered`(반대 결과)로 판정했고, 모든 체결에서 테이커와 메이커 중 정확히 한쪽만 이겼다.

| 항목 | 값 |
| --- | ---: |
| 테이커 전체 수익률 | **−9.2%** (2,952만 냄 → 2,681만 받음) |
| 메이커 전체 수익률 | **+20.7%** |
| 손해 본 계정 비율 | 52.3% (계정당 손익 중앙값 −5 HSK, 하위 10%는 −248 HSK 이하) |
| 주로 메이커인 계정 11,571개 손익 | +259만 HSK |
| 주로 테이커인 계정 27,952개 손익 | −210만 HSK |
| 상위 100개 계정이 가져간 이익 | 162만 HSK (전체 이익 410만의 40%) |
| 테이커가 손해 본 이벤트 비율 | 74.8% (이벤트별 테이커 수익률 중앙값 −68.8%) |

| 마감까지 남은 시간 | 체결 | 테이커가 낸 HSK | 테이커 수익률 | 가격 중앙값 | 실제 적중률 |

| 1~6시간 | 22,545 | 3,112,100 | **−62.2%** | 0.85 | 21% |

- 마감 24시간 안의 손실(351만 HSK)은 **316개 이벤트, 22,751명**에 퍼져 있다. 상위 5개 이벤트가 32%, 상위 10명이 2.3%를 차지한다. 일부 고래나 일부 시장의 문제가 아니다.
- 마감 직전 테이커는 **"거의 확실해 보이는 쪽"(가격 0.85~0.89)을 사는데, 실제로는 1~37%만 맞았다.** 가격이 현실의 진행 상황(예: 기초자산 가격)을 따라가지 못한 상태에서, 정보를 가진 메이커가 반대편에 서 있었던 것으로 보인다. 이 부분은 해석이고, 이벤트 제목과 기초자산 데이터로 확인해야 한다.

## 4. 이것이 Track 1과 맞는가

| 공고의 개발 방향 | 예측시장 거래 에이전트에서 |
| --- | --- |
| 실시간 시장·온체인 데이터 모니터링 | 체결·호가(체인 위 확인 이벤트)와 기초자산 가격(예: NVDA) |
| AI 기반 전략과 신호 분석 | 결과 확률을 외부 데이터로 추정하고, 시장 가격과 비교 |
| 차익거래·스프레드 탐색 | 시장 가격과 추정 확률의 차이, 관련 결과끼리의 가격 모순(≥180, ≥185, ≥190) |
| 자동 주문과 포지션 관리 | 사거나, 주문을 걸거나, 사지 않기 |
| 손절 같은 위험 관리 | 마감 직전 매수 차단, 한도 |
| 손익을 보여 주는 대화형 화면 | 이벤트별·시점별 손익 |

공고 문구는 "HSKSwap 같은 DEX"라고 예를 든다. 예측시장이 DEX가 아니라는 반박은 나올 수 있다. 다만 공고의 개발 방향 6개와는 모두 맞는다.

## 5. 남은 확인

| 항목 | 왜 중요한가 |
| --- | --- |
| 서비스 이름과 외부 API 유무 | 사용자 지갑은 플랫폼이 대신 처리한다. 우리 에이전트가 주문을 낼 수 있는지는 API에 달렸다 |
| 이벤트 제목(체인에는 해시만 있음) | "마감 직전 가격이 현실을 못 따라간다"는 해석을 확인하는 데 필요하다 |
| 판촉 자금 비중 | 사용자가 잃은 돈 중 자기 돈이 얼마인지. 판촉 자금이 많으면 페인의 무게가 줄어든다 |
