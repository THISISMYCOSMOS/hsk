HashKey Horizon Seoul · Track 1 AI Agent Trading · 2026-11-24 정리본
제출 마감 **12월 3일 13:00 KST** · 필수 **HSK Chain 메인넷 스마트 컨트랙트 배포** ([공식 공고](https://luma.com/mwn8lt3q))
근거: [01-market-check.md](01-market-check.md) · 반박과 해결: [02-faq-adversarial.md](02-faq-adversarial.md) · 다른 후보: [03-candidates.md](03-candidates.md)

> HSKSwap에 범위를 정해 유동성을 공급한 사람이 하락장에서 손실 꼬리를 자르려면, 가격이 하단에 가까워질 때 얼마를 빼고, 뺀 WHSK를 팔지 말지 정해야 한다. 지금은 화면을 보다가 직접 빼거나 그냥 둔다. 그대로 두면 하단 아래로 떨어지는 동안 USDT가 모두 WHSK로 바뀐다. 우리는 **회수를 계약 규칙으로 자동화하고, 처분(매도·보유)과 재공급 판단을 AI가 사용자 한도 안에서 하도록** 바꾼다.

**판정: 해커톤 기준 조건부 유지, 사업 기준 보류.** 이유는 11절에 있다.

## 1. 타겟 사용자와 상황

### 누구인가

**HSKSwap WHSK/USDT 풀에 범위를 정해(집중 유동성) 공급하는 개인 LP**를 대상으로 한다.

- **이 체인에는 아직 없다.** 살아 있는 LP NFT 21개 중 집중 범위는 시험용 몇 개뿐이다. 실제 유동성은 운영 주소가 전 구간으로 공급한다(01 문서 3-1, 3-2).
- **없는 이유는 숫자로 설명된다.** 10/16 이후 수수료는 163달러였고, HODL 대비 손실은 1,215달러였다. 범위를 좁혀도 이 비율은 같다(01 문서 3-4).
- 그래서 이 제품은 "LP로 돈을 번다"를 약속하지 않는다. **"LP를 하기로 했다면 하락장에서 손실 꼬리를 자른다"**만 약속한다.

### 상황

- 범위를 좁게 잡을수록 수수료를 많이 받지만, 하단 근처에서 WHSK 비중이 빠르게 커진다.
- 하단을 뚫으면 포지션이 전부 WHSK가 되고, 그 뒤의 하락을 그대로 맞는다.
- 계속 지켜볼 수 없다. 이 풀은 얇아서 순간 가격이 쉽게 흔들린다(10/16 빈 풀에서 0.63달러 스왑이 가격을 10% 움직였다).

### 예시 페르소나 (가상)

> HSK를 장기 보유하는 개인. WHSK 6,000개와 USDT 500개(약 1,000달러)를 지금 가격 ±10% 범위에 넣고 싶다. 수수료는 덤이고, 하락장에서 원금이 크게 깨지는 것만은 막고 싶다. 하루에 몇 번만 확인할 수 있다.

## 2. 제품이 하는 일

행동을 세 단계로 나누고, 단계마다 맡는 주체를 다르게 둔다. 근거는 02 문서 Q4의 실험이다.

| 단계 | 하는 일 | 맡는 주체 | 실험 근거 (±10%, 하단을 건드린 33개 구간) |
| --- | --- | --- | --- |
| **① 회수** | 하단에 가까워질수록 더 많이 뺀다. 기본값: 하단 +10%에서 20%, +5%에서 30%, 하단에서 50% | **계약 규칙** (누구나 호출 가능) | 그냥 두기보다 28개에서 나음, 평균 +2.3%p. 결과가 꾸준해서 판단이 필요 없다 |
| **② 처분** | 회수한 WHSK를 팔지, 들고 있을지 | **AI** (사용자가 켜고, 한도를 정했을 때만) | 매도는 급락에서 최대 +40%p, 흔들림에서 최대 −9%p. 성과가 여기서 갈린다 |
| **③ 재공급** | 언제, 어느 범위로 다시 넣을지 | **AI 제안 → 사용자 승인** | 운영 주소도 나눠서 재공급했다(10/16, 10/30). 첫 버전은 자동 실행하지 않는다 |

- **회수를 멈추는 판단:** 일시적 흔들림이라고 판단하면, AI가 다음 단계 회수를 **최대 N시간** 늦출 수 있다. 늦출 수만 있고 취소는 못 한다. 계약이 정한 최대 지연이 지나면 회수는 실행된다.
- **상단 이탈:** 첫 버전은 알림과 재공급 제안만 한다(02 문서 Q6).

## 3. 판단에 쓰는 값

| 값 | 출처 | 쓰는 곳 |
| --- | --- | --- |
| 풀 순간 가격, 30분 TWAP | 풀 `slot0`, `observe` (기록 240칸 확인) | **계약이** 회수 조건과 매도 최소 수령액을 확인 |
| 풀 유동성, 수량별 견적 | 풀 `liquidity`, Quoter | 매도 손해 계산 |
| 거래소 가격 | HTX(24시간 약 77만 달러), MEXC(약 5.6만), Gate(약 2.7만), KuCoin(약 1.2만) | **AI가** 추세 판단. 풀과의 차이도 입력으로 쓴다 |
| 최근 수익률, 변동성 | 거래소 1분·1시간봉 | 흔들림인지 추세인지 |
| BTC 흐름 | Hyperliquid·Coinbase | 시장 전체 하락인지 HSK만의 하락인지 |
| 포지션 상태 | NPM `positions(tokenId)` | 남은 유동성, 쌓인 수수료 |

거래소 가격은 **계약이 믿지 않는다.** AI 판단의 입력으로만 쓰고, 판단마다 입력값의 해시를 체인에 남긴다.

| ⑦ 재공급 제안 | 승인하거나 무시한다 | 가격이 안정되면 새 범위와 수량을 제안한다 |

## 5. 계약 설계 (메인넷 배포 대상)

### `LPGuard` 한 개 계약

```text
deposit(tokenId, Plan)          // NFT를 받으며 계획 기록. Plan = 단계[(가격, 비율)], TWAP 창, 순간·TWAP 최대 차이,
                                //   처분 허용, 회당·하루 한도, 최소 수령 비율, 에이전트 주소, 최대 지연, 만료
poke(tokenId)                   // 누구나 호출. 조건이 맞는 단계의 decreaseLiquidity + collect 실행
delay(tokenId, step, until, h)  // 에이전트 전용. 최대 지연 이내로만. h = 판단 입력 해시
sell(tokenId, amount, minOut, h)// 에이전트 전용. 처분 허용·한도·TWAP 기준 최소 수령액 확인 후 풀에서 매도
proposeReprovide(tokenId, ...)  // 에이전트 제안 기록. 실행은 소유자 승인 시
pause / withdrawNFT / withdrawTokens   // 소유자 전용, 언제든
```

| 계약이 강제하는 것 | 이유 |
| --- | --- |
| 회수·매도 대금은 **소유자 몫으로만** 쌓이고 소유자만 꺼낸다 | NPM은 승인된 주소가 받는 주소를 마음대로 정하게 둔다(01 문서 2-2). 에이전트 지갑에 직접 승인을 주면 안 된다 |
| 회수는 TWAP 조건 + 순간·TWAP 차이 한도 | 얇은 풀에서 가격을 잠깐 밀어 회수를 유도하는 공격 방지(02 문서 Q7) |
| AI는 회수를 늦출 수만 있고 취소는 못 한다 | AI가 틀리거나 멈춰도 손실 꼬리 자르기는 작동해야 한다 |
| 매도는 회당·하루 한도, TWAP 대비 최소 수령액 | 키 탈취 시 최악을 "하루 한도만큼 나쁜 시점의 매도"로 제한 |
| 모든 판단의 입력 해시와 모델 버전을 이벤트로 남김 | 사후에 같은 입력으로 다시 판단해 볼 수 있음 |

**확장(후보 2):** `Plan`에 깊이 하한("1만 HSK 매도 손해 X% 이하")을 넣으면, 계약이 회수 뒤 남는 유동성으로 손해를 계산해 지켜질 때만 회수한다. 운영 주체용 모드다. 첫 출품에서는 기능만 넣고, 사용자로 내세우지 않는다(03 문서).

| 상황 | 처리 |

| 순간 가격과 TWAP 차이가 한도를 넘음 | 회수를 보류한다. 차이가 줄면 다시 확인한다 |

## 8. 검증

### 8-1. 과거 재생 (이미 한 것)

01 문서 3-6에 있다. 실제 풀 가격으로 57개 구간을 30일씩 재생했다. 회수 규칙의 효과(28/33)는 확인했다. 처분의 효과는 시장 국면에 따라 갈린다는 것도 확인했다.

### 8-2. 처분 판단 비교 (출품 전까지 할 것)

| 비교군 | 처분 규칙 |
| --- | --- |
| A | 항상 보유 (회수만) |
| B | 항상 매도 |
| C | 단순 규칙: 거래소 24시간 수익률이 −X% 이하이면 매도 |
| D | AI 판단 |

- 같은 57개 구간, 같은 비용 조건으로 비교한다. 지표는 USDT 대비 평균·최악, HODL 대비 평균, 흔들림 구간에서 잃은 횟수다.
- AI는 그 시점까지의 데이터만 보게 한다. 구간마다 입력과 출력을 저장해 다시 돌려 볼 수 있게 한다.
- **D가 C를 이기지 못하면 AI 차별점은 보류한다.** 그때는 "회수는 계약이 지키고, 판단은 기록으로 검증된다"를 가치로 내세운다.

**A·B·C는 미리 돌려 봤다** ([scripts/bt_rule.py](scripts/bt_rule.py), ±10%, 하단을 건드린 33개 구간, USDT 대비)

| 비교군 | 평균 | 최악 | A보다 나음 / 못함 |
| --- | ---: | ---: | ---: |
| A 항상 보유 | −13.6% | −36.7% | |
| B 항상 매도 | **−6.0%** | **−10.0%** | 15 / 18 |
| C 24시간 수익률 −3% 이하면 매도 | −8.3% | −25.0% | 15 / 18 |
| C 24시간 수익률 −5% 이하면 매도 | −9.1% | −29.4% | 14 / 10 |
| C 24시간 수익률 −8% 이하면 매도 | −13.6% | −36.7% | 3 / 7 |

- 단순 하락률 규칙은 "항상 매도"를 이기지 못했다. 5월처럼 **천천히 계속 내리는 하락**을 놓치기 때문이다. 추세 판단이 쉽지 않다는 뜻이고, AI가 들어갈 자리이기도 하다.
- 이 기간은 하락장이라 "항상 매도"가 유리했다. AI의 실제 비교 상대는 **B**다. B는 흔들림 구간 18개에서 A보다 못했다. AI가 이 18개 중 일부를 피하면서 급락 구간을 지키는지가 기준이다.
- 이 풀의 가격 기록은 2026년 2월부터라서, 상승장 구간으로 따로 검증할 데이터가 없다. 이것은 남는 한계다.

### 8-3. 메인넷 실작동

- 실포지션: 200~500달러, ±10% 범위. 가드 계약에 맡겨 마감까지 운영한다.
- 시연 포지션: 50~100달러, ±3% 범위. 짧은 기간 안에 단계 회수가 실제로 일어나는 것을 보인다.
- 모든 실행은 블록 번호와 거래 해시로 발표 자료에 남긴다.
