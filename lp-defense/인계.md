## 1. 사용자 원칙 (가장 중요)

- **편향 금지가 1순위다.** 이전 대화를 참고하되 그 방향으로 기울지 않는다. 우리 기획에 유리한 결과만 고르지 않고 불리한 결과도 그대로 적는다.
- 여러 번 물어봐도 억지로 결론을 바꾸지 않고 소신껏 최선의 안을 고른다. 다만 **새 근거**가 나오면 바꾸고 왜 바꿨는지 밝힌다(11-26 실제 사례, 8절).
- 작업 브랜치: `claude/pensive-lovelace-e9b9pi` (저장소 THISISMYCOSMOS/hsk). 다른 브랜치에 푸시하지 않는다. PR은 요청이 있을 때만.
- 메인넷 배포, 서명, 팀 자금 이동은 팀의 명시적 승인 없이는 하지 않는다.
- 막힌 것은 우회하지 않고 이유와 함께 적는다(DoraHacks, Notion).
- 시험 결과는 통과·실패를 그대로 보고하고, 보고는 한국어로 결론부터 짧게.
- 사용자는 팀원(유진님)에게 보낼 메시지를 자주 부탁한다. **사용자 말투(해요체, 짧은 문장)로, 번호·소제목 없이 산문으로** 원할 때가 있다. 보내기 전 **팩트 체크를 먼저** 한다. 사용자의 음성 입력 오타를 바로잡는다(HFK → HSK, 카오 프로토콜 → CoW Protocol 등). 메시지를 팀원에게 직접 보낼 수단은 없다(사용자가 복사해서 보냄).

## 4. 11-25 구현 (LP 기획 기준, `구현-계획.md` 11-25~11-26 범위)

### 4-1. 계약 `app/contracts` (Foundry)

- 설치: (이전 환경) Foundry 1.5.1을 공식 릴리스 tar에서 받아 `/root/.foundry/bin`에 풂. 다른 환경에서는 `foundryup` 등으로 설치. solc 0.8.28, `evm_version = cancun`(HSK 메인넷에서 PUSH0·TLOAD·MCOPY eth_call 확인), optimizer 200. `lib/forge-std` v1.17.0을 커밋해 둠. forge는 자체 User-Agent를 보내 RPC 403이 나지 않음.
- 인터페이스(소스 복사 없이 형식만): `INonfungiblePositionManager`, `IUniswapV3Factory`, `IUniswapV3Pool`, `ISwapRouter02`(deadline 없는 7필드), `IQuoterV2`, `ISupraOraclePull`, `IERC20Minimal`.
- `LPGuardVault`: `deposit`(소유자 확인, NPM `positions` → `getPool`로 등록 풀 확인, token1=USDT, 유동성>0, 정책 검사, `safeTransferFrom` + transient 플래그로 그 NFT만 받음), `withdraw`(언제든, pendingSell 반환, 기록 삭제 후 전송), `onERC721Received`(deposit 중 NPM에서 오는 것만), `getPosition`, `isSupportedPool`, `pairIndexOf`, `policyError`. 재진입 잠금(transient). 관리자 변수 없음.
- 생성자에서 주소 묶음 확인(NPM·Router의 factory 일치, Supra 코드 존재, 두 풀 다름, 풀 token1=USDT, `getPool` 일치, pairIndex≠0) → 틀리면 `BadConfig(code)`.
- 정책 오류 코드 `InvalidPolicy(code)`: 1 회수선(기준가 > 선1 > 선2 > 선3 > 선4 > 0 아님), 2 누적 비율(0 < … < 10000으로 끝나지 않음), 3 매도 손실 > 500bps, 4 오라클 차이 > 1000bps, 5 오라클 유효 시간 0 또는 600 초과, 6 앞당기기 > 1, 7 만료 ≤ 지금.
- 명세와 다르게 더한 것: 오류 `EmptyPosition`, `UnexpectedNFT`, `NotDeposited`, `Reentrancy`, `TransferFailed`, `BadConfig`. `line[3]`이 NFT 범위 하단과 같은지는 확인 안 함(TickMath GPL 회피, 자금 안전과 무관).
- 안 한 것: `executeStep`, `sellPending`, `updatePolicy`, `setPaused`, `priceStep`(11-27~).
- 시험 `test/LPGuardVault.fork.t.sol`: 블록 30,620,000 고정 포크(`HSK_RPC`, `FORK_BLOCK` 환경변수로 변경). `forge test`와 `forge test --fork-url https://mainnet.hsk.xyz` 둘 다 **17/17 통과**. F1 주소·풀·slot0·기존 NFT 읽기, F2 `deal`로 WHSK·WETH·USDT 받고 mint(위험 목록의 "`deal`이 안 됨"은 일어나지 않음), F3 approve/setApprovalForAll → deposit → getPosition → withdraw. 거부: 남의 NFT, 승인 없음(NPM 메시지 확인), 다른 수수료 풀(WHSK/USDT 1%를 포크에서 생성), USDT 아닌 풀(WHSK/WETH), 유동성 0, 정책 코드 1~7과 경계값 통과, 직접 전송(UnexpectedNFT), onERC721Received 직접 호출, 남의 인출, 두 번 인출, 만료 후 인출 허용, 생성자 BadConfig.

### 4-2. 에이전트 `app/agent` (Node 22 + TypeScript)

- 의존성(2주 이상 된 고정 버전): viem 2.57.17, @hskswap/sdk-core 1.0.3, typescript 5.9.3, tsx 4.23.15, @types/node 22.20.5. vitest 5는 npm 피어 오류로 빼고 Node 내장 `node:test` 사용.
- `config.ts`: sdk-core에서 factory·NPM·router·quoter·WHSK를 가져와 문서 값과 대조, 다르면 시작 중단. WETH·USDT·Supra는 문서 값. 두 풀과 Supra 쌍 번호(WETH 1, WHSK 517). 환경변수 `HSK_RPC`, `HSK_USER_AGENT`, `SUPRA_PROOF_URL`, `SUPRA_TIMEOUT_MS`.
- `chain.ts`: 체인 177, User-Agent 헤더, viem http 재시도(408/413/429/5xx, 지수 백오프), 403은 재시도 안 함.
- `pools.ts`: 같은 블록 고정 `slot0`·`liquidity`, 풀 설정 체인 대조, NFT `positions`·`ownerOf`, 지갑 NFT 목록. `price.ts`: sqrtPriceX96→가격, 자리 맞춤, 차이 bps. `supra.ts`: `get_proof`(시간 초과·HTTP·형식 오류 구분), `verifyOracleProofV2` eth_call 검증(ms→초). `cli.ts`: `npm run read -- 14`.
- 시험: 단위 **13/13**, 메인넷 읽기 **5/5**. 단위 하나(`scaleToE18`)는 처음에 시험 쪽 기대값을 잘못 적어 실패 → 기대값만 고쳐 통과(코드 변경 없음).
- 안 한 것: Swap 로그 캐시, 신호, `GET /api/pools`(11-26 나머지).

## 7. 사용자가 받은 메시지 초안 (요지)

- 리스크 반박(사용자 말투, 1~3번): ① 거래가 적어도 차익거래가 풀 가격을 외부에 맞춤(상관 0.9, −50.9% vs −50.7%) ② 거래가 적으면 수수료가 적어 손실을 못 메움(263 vs 967) → 리스크 관리가 더 필요 ③ 들어왔던 개인 LP는 소액이었고 손해(20 USDT → 15.4, 범위 LP −26%). "기획 타당성 충분히 증명"·"2월에 꽤 들어왔다 다 빠졌다"·"5월 이후 없다"는 팩트 체크에서 틀리거나 과장이라 고쳐 줌. "LP가 외부 가격에 맞춘다" → "차익거래가 맞춘다"로 고침.
- 매칭 반박(산문): 거래처가 HSKSwap 하나라 싼 경로 찾기는 대상이 적고, 직접 매칭 절감 상한이 월 수십 USDT라 거래량 부족에 더 치명적, CoW가 이미 있어 차별성 약함 → LP는 문제를 데모로 보여 줄 수 있고 매칭은 보여 줄 게 적다. (이후 유진님 재반론으로 일부 무효, 6-5절)
- 유진님 매크로 질문 답장: LP 증가는 확신 못 함, 매칭도 같음, 데모 성과 면에서 매칭이 나아 매칭으로 가는 데 동의, 상대 주문 적음·CoW 원리 같음은 발표 때 먼저 밝히기.
- "LP 하는 사람이 많냐": HSK에는 거의 없음, 다른 체인에는 많음(개인 비중 모름).

## 8. 주제 판단의 흐름과 현재 입장

1. 유진님 1차 피드백 → 위험은 실재, 사용자 없음은 맞음 → LP 유지 권함.
2. 매칭 1차 검토(상대 주문 없음, 절감 상한 월 약 50 USDT, CoW와 같음) → LP 유지 권함.
3. 유진님 재반론(1·8번, WETH 가격 충격, 실제 가상 지갑 시험, 팀 확신)은 **새 근거** → 입장 수정.
4. **현재 입장: 매칭으로 가는 데 동의.** 근거는 데모 객관성(같은 블록 전후 비교)과 팀 확신. 제품 가치(사용자 1명의 이득)만 보면 LP가 조금 낫다는 의견도 함께 전달.
5. 매칭으로 갈 때 조건: 가치는 WETH 풀·큰 주문으로 보여 줄 것(WHSK 소액은 절감이 수수료뿐). 상대 주문이 적다는 점(30일 지갑 30개, 봇 95%)과 CoW와 같은 원리라는 점을 발표에서 먼저 밝힐 것. 차별점은 "HSK 체인 얕은 풀에 맞춘 즉시 비교". AI 역할은 "견적이 체결까지 남을지 판단"(약함, 인정). 미리 서명한 지정가 주문은 불리할 때 먼저 체결되는 위험 → 가격 한도·만료로 묶기. 계약은 EIP-712 서명 주문 검증 + 부분 체결 + 직접 교환과 잔량 DEX 매도를 한 거래로(잔량 실패 시 모두 되돌림).

## 12. 환경 메모

아래 중 "이 환경"은 이전 작업 환경(Claude 클라우드 컨테이너, 프록시 경유)을 뜻한다. Codex 등 다른 환경에서는 Foundry 설치, 프록시, 접근 차단 여부가 다를 수 있다.


- HSK RPC `https://mainnet.hsk.xyz`: User-Agent 없으면 403. `eth_getLogs` 5,000블록까지. 과거 블록 `eth_call` 가능. 블록 약 2초(하루 43,200블록). Cancun 명령어 지원. 최신 블록 약 30,663,000(11-26).
- Supra 증명: `POST https://rpc-mainnet-dora-2.supra.com/get_proof` `{"pair_indexes":[1,517],"chain_type":"evm"}` → `proof_bytes`(0x 없음). 키 불필요. ETH/USDT=1, HSK/USDT=517.
- Node 22 기본 fetch는 `NODE_USE_ENV_PROXY=1`이 있어야 이 환경 프록시를 탐(npm 스크립트에 넣어 둠).
- 외부 시세: Binance는 `data-api.binance.vision`만 됨(api.binance.com 지역 차단). HSK는 Binance에 없음 → Gate.io(1시간, 최근 1만 개까지, 1분은 약 7일만), KuCoin(1분, 기간 제한 없음). OKX·Bybit은 막히거나 종목 없음.
- Blockscout API(`rpc.py`의 `bs`)로 주소 정보·토큰 목록·검색. 요청 간격 2초.
- Notion: 사용자 링크 페이지는 연결된 계정에서 404. DoraHacks: 405. 둘 다 우회하지 않음.
- 원자료는 커밋하지 않는다. 데이터 폴더에서 `python3 <scripts>/fetch.py chain`(약 2분), `python3 <scripts>/ext.py <데이터>/ext.json`. 분석: `risk_direct.py`, `risk_lag.py`, `pos_now.py`, `match_overlap.py`, `venues.py`(모두 `lp-defense/scripts/`).
