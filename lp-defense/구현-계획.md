# 구현 계획

2026-11-25 작성. 제출 마감은 12-03 13:00 KST다. `빌드-계획.md`(11-24)를 이 문서가 대신한다. 명세는 `API-명세.md`, 화면은 `사용자-플로우.md`, 도구와 주소는 `개발-가이드.md`를 따른다.

## 1. 원칙

- 해커톤 코드는 새 저장소에서 새로 작성한다(독창성 조건). 공개 GitHub 저장소를 권한다. 이 저장소의 백테스트 스크립트는 근거 자료로 링크만 한다.
- 계약이 안전을 강제하고, 에이전트는 계약이 허용한 범위에서만 판단한다. 에이전트 버그가 사용자 자금을 잃게 만들면 안 된다.
- 메인넷 배포, 팀 자금 이동, 실거래는 팀의 명시적 승인 후에만 한다.
- 막히면 그날 안에 범위를 줄인다(9절 순서).

```

    src/LPGuardVault.sol

    test/LPGuardVault.t.sol           단위 시험 (모의 NPM·라우터·오라클)
    test/LPGuardVault.fork.t.sol      메인넷 포크 시험
    script/Deploy.s.sol
  agent/                     Node 22 + TypeScript
    src/config.ts            주소, 체인, 기본 정책
    src/chain.ts             RPC 클라이언트(User-Agent 헤더), 재시도
    src/pools.ts             slot0, liquidity, Swap 로그 캐시(5,000블록 단위)
    src/signals.ts           거래대금 비율, 순매도, 7일 고점 대비, 유동성 변화
    src/supra.ts             get_proof
    src/sizing.ts            매도 비용 계산식, Quoter 대조, 나눠 팔기
    src/decide.ts            단계 판단, 앞당기기, 하단 판단, 보류
    src/execute.ts           eth_call 모의 → 전송 → 영수증
    src/explain.ts           LLM 설명 문장, 채팅 도구
    src/server.ts            REST API (Fastify)
    src/db.ts                SQLite
  web/                       Vite + React + wagmi + viem
  docs/                      기획안, API 명세, 데모 대본, 공식 도구 표
```

라이브러리: 계약의 곱셈·나눗셈은 OpenZeppelin `Math.mulDiv`(MIT)를 쓴다. Uniswap v3 라이브러리 원본은 GPL이고 0.7.6용이라 복사하지 않는다. 주소와 토큰 상수는 `@hskswap/sdk-core`에서 가져온다.

## 5. 에이전트 구현 순서

1. `chain.ts`: viem 클라이언트, 체인 177 정의, User-Agent 헤더, 429·5xx 재시도.
2. `pools.ts`: `slot0`, `liquidity`. Swap 로그는 마지막으로 받은 블록부터 5,000블록씩 이어 받아 SQLite에 쌓는다.
3. `signals.ts`: 24시간 거래대금 ÷ 7일 일평균, 24시간 순매도 ÷ 거래대금, 7일 고점 대비 하락, 풀 유동성 ÷ 24시간 중앙값. 기준값은 백테스트와 같은 1.5배, 30%, −5%, 50%를 쓴다.
4. `supra.ts`: 실행 직전에만 증명을 받는다. 실패 시 보류.
5. `sizing.ts`: `받는 USDT = P·Δx(1−f) ÷ (1 + Δx(1−f)·√P / L)`로 손실 1.2% 이하가 되는 최대 Δx를 이분 탐색으로 구한다.
6. `decide.ts`: `사용자-플로우.md` 3절 순서를 그대로 구현한다. 판단마다 `decisions`에 한 줄을 쓴다.
7. `execute.ts`: `simulateContract` → `writeContract` → 영수증. 같은 단계를 두 번 보내지 않도록 대기 중인 거래가 있으면 건너뛴다.
8. `explain.ts`: 판단 기록과 숫자를 LLM에 넘겨 두세 문장 설명을 만든다. LLM이 실패하면 틀(템플릿) 문장을 쓴다.
9. `server.ts`: `API-명세.md` 2절의 엔드포인트.

## 7. 메인넷 배포 체크리스트 (팀 승인 후)

1. 포크 시험 F1~F16 통과, 계약 커밋 동결.
2. 팀이 배포 지갑, 가스용 HSK(배포 약 2 HSK + 실행 여유 20 HSK 권장), 데모 LP 자금(50~100 USDT 상당)을 승인한다. 개인 키는 문서·저장소에 쓰지 않는다.
3. `forge script script/Deploy.s.sol --rpc-url https://mainnet.hsk.xyz --broadcast`.
4. `forge verify-contract <주소> LPGuardVault --verifier blockscout --verifier-url https://hsk.blockscout.com/api/ --chain-id 177`. 안 되면 Blockscout 화면에서 표준 JSON 입력으로 올린다.
5. 배포 직후 고정값(npm, router, usdt, supra, pairIndex)을 체인에서 읽어 기록한다.
6. 기록: 계약 주소, 배포 거래 해시, 검증 링크, 고정값. 이어서 팀 NFT 예치·실행 거래 해시와 받은 금액.

## 9. 늦어질 때 빼는 순서

1. 백테스트 화면 → 정적 이미지로 대체
2. 채팅 → 결정 기록과 틀 문장 설명만
3. AI 앞당기기(`accelSteps`) → 0으로 고정
4. `sellPending` 나눠 팔기 → 데모 금액을 작게 해서 한 번에 판다
5. 하단 AI 판단 → "전부 빼기" 고정

끝까지 지킬 것: 메인넷 배포와 소스 검증, 포크에서 통과한 한 단계 실행과 되돌림, 메인넷 실행 1회, 감시 화면, 한계를 밝힌 발표.
