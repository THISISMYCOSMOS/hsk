# 사용자 플로우

2026-11-25 작성. 화면 순서, 에이전트 실행 흐름, 예외 흐름, 3분 데모 순서다. 화면 문구는 예시이고, 숫자는 API(`API-명세.md`)에서 받는다.

## 1. 전체 흐름

```
지갑 연결 → 포지션 고르기 → 보호 설정(미리보기·비용 확인) → 맡기기(서명 2번)
   → 감시 화면 ──(가격이 회수선 도달)──> 에이전트 실행 → 알림·결과 → 감시 계속
   │                                         └─(조건 미달)─> 보류·사유 기록
   ├─ 채팅으로 질문
   └─ 설정 변경 / 일시정지 / 인출(언제든)
```

## 2. 화면별 흐름

### 0단계: 지갑 연결

- MetaMask 또는 OKX Wallet을 연결한다. HSK Chain(체인 177)이 없으면 추가를 요청한다(RPC `https://mainnet.hsk.xyz`, 탐색기 `https://hsk.blockscout.com`).
- 첫 화면에 "이 도구는 큰 손실을 줄이는 대신 비용을 냅니다. 수익을 늘리는 도구가 아닙니다."를 한 줄로 보여 준다.

### 1단계: 포지션 고르기

- `GET /api/wallets/:address/positions`로 HSKSwap NFT 목록을 보여 준다.
- 카드마다 풀, 범위, 범위 안/밖, 토큰 수량, 지금 가치, "그냥 들고 있었다면"과의 차이를 보여 준다.
- 지원하지 않는 풀(WBTC, 다른 수수료 등급)과 전 구간 포지션은 회색으로 두고 이유를 적는다. 전 구간 포지션에는 "하단"이 없다.

### 2단계: 보호 설정

| 입력 | 기본값 | 설명 문구 |
| --- | --- | --- |
| 기준가 | 지금 풀 가격 | "이 가격에서 하단까지를 네 구간으로 나눠요." |
| 회수 비율 | 균등 25%씩 | 선택지: "강한 방어(40·30·20·10)는 하락장에서 더 지키지만, 평소 비용도 더 커요." |
| 한 번 매도 최대 손실 | 1.5% | "넘으면 나눠 팔아요." |
| 외부 가격 대비 허용 차이 | 3% | "HSKSwap 가격이 외부보다 이만큼 넘게 낮으면 팔지 않아요." |
| AI 앞당기기 | 끔 | 켜면: "위험 신호가 강할 때 다음 단계를 한 단계 먼저 실행할 수 있어요." |
| 하단에서 남은 LP | AI 판단(기본 전부 빼기) | "되돌아올 근거가 뚜렷할 때만 남겨요." |
| 실행자 | 우리 에이전트 주소 | "이 주소는 정해진 단계 실행과 매도만 할 수 있어요. 돈을 다른 곳으로 보낼 수 없어요." |
| 만료 | 30일 후 | - |

미리보기(`POST /api/positions/:tokenId/preview`)에 보여 줄 것:
- 가격 그래프 위 회수선 4개와 각 지점에서 뺄 양, 예상 USDT, 매도 비용.
- 두 방향 표: 하단까지 떨어지면 지키는 금액, 기준가로 돌아오면 포기하는 금액.
- 백테스트 요약([모의] 표시): 하락장에서 줄인 손실, 평소 비용. 수수료가 많은 풀에서는 평균이 손해일 수 있다는 문장도 함께 넣는다.
- 비용 고지: "이 범위 LP는 지난 1년 평균으로 반반 들고 있기보다 못했어요." [모의]
- 포지션이 WETH 풀에서 2,000 USDT를 넘으면 "풀이 얇아 효과가 줄어요. 나눠 팔기가 늘어나요."를 보여 준다.

### 3단계: 맡기기

1. "NFT 사용 승인" 서명(`approve`, `POST /api/tx/build {action:"approve"}`).
2. "보호 켜기" 서명(`deposit`).
3. 완료 화면에 Blockscout 거래 링크와 "언제든 꺼내기 버튼으로 돌려받을 수 있어요."를 보여 준다.

### 4단계: 감시 화면

| 영역 | 내용 |
| --- | --- |
| 상태 | 보호 켜짐/꺼짐, 완료 단계(0~4), 만료일 |
| 가격 | 풀 가격, 외부 가격(Supra), 차이 %. 차이가 1% 넘으면 노란색, 3% 넘으면 빨간색. Track 1의 "스프레드 탐지" 항목이 이것이다. |
| 다음 행동 | "다음 회수선 0.0790까지 2.3% 남음, 그때 LP의 25%를 빼요." |
| 신호 | 거래대금(평소 대비), 순매도 비율, 7일 고점 대비 하락, 풀 유동성 변화 |
| 기록 | 실행·보류 목록과 이유(`GET /api/positions/:tokenId/decisions`) |
| 비교 | 지금까지 결과: LP 그대로 뒀다면 / 실제 / 그냥 들고 있었다면 |

### 5단계: 실행 알림과 결과

- 알림 예: "가격이 첫 회수선(0.0790) 아래로 내려와 LP의 25%를 뺐어요. WHSK 153개를 12.3 USDT에 팔아 지갑으로 보냈어요(외부 가격 대비 −0.6%). 더 떨어지면 하단까지 약 2.5 USDT를 지키고, 기준가로 돌아오면 약 0.8 USDT를 포기해요."
- 결과 카드: 뺀 유동성, 받은 USDT, 함께 받은 수수료, 금고에 남은 위험자산, 거래 링크.

### 6단계: 채팅

질문 예와 답의 근거:

| 질문 | 쓰는 도구 |
| --- | --- |
| "지금 25% 빼면?" | `scenario` |
| "왜 아까 뺐어?" / "왜 안 팔았어?" | `get_decisions` |
| "이 규칙 예전에도 효과 있었어?" | `get_backtest` ([모의]로 답함) |
| "보호 잠깐 꺼 줘" | `propose_tx` → 사용자가 서명 |

### 7단계: 변경, 중지, 인출

- 정책 변경과 일시정지는 사용자 서명 한 번이다.
- 인출은 언제든 된다. NFT(남은 유동성 포함)와 팔지 못한 위험자산을 돌려받는다.

## 3. 에이전트 실행 흐름 (1분마다)

```
1. 금고의 활성 포지션 목록 읽기 (이벤트 + getPosition)
2. 풀별: slot0, liquidity, 최근 Swap 로그 → 신호 계산 → pool_snapshots 저장
3. 포지션별:
   a. priceStep 계산. 다음 단계 가격에 안 닿았으면:
        - AI 앞당기기 허용 && 위험 신호 켜짐 → 4로
        - 아니면 종료
   b. 하단 단계면 AI 판단: 남길 근거가 뚜렷하면 보류(bottom_keep) 기록 후 종료
   c. 에이전트 보류 조건: 풀 유동성 < 24시간 중앙값의 50% → hold 기록 후 종료
4. Supra 증명 받기 (실패 → hold 기록, 다음 분에 재시도)
5. 매도량 정하기: 계산식으로 손실 ≤ 1.5% − 여유 0.3%가 되는 양, 최대 = 이번에 나올 위험자산
6. executeStep을 eth_call로 모의 실행
     - 성공 → 실제 전송
     - Too little received → 매도량 절반으로 다시 (최대 3번, 그래도 실패면 sellAmount=0으로 회수만)
     - PoolBelowOracle / OracleStale → hold 기록
7. 영수증 확인 → decisions 기록 → LLM이 설명 문장 생성 → 알림
8. 금고에 남은 위험자산이 있으면 다음 분부터 sellPending으로 나눠 판다
```

## 4. 예외 흐름

| 상황 | 계약 | 에이전트 | 사용자에게 |
| --- | --- | --- | --- |
| 풀 가격이 외부보다 3% 넘게 낮음 | `PoolBelowOracle`로 거부 | 보류 기록, 다음 분 재확인 | "HSKSwap 가격이 외부보다 낮아 기다리는 중이에요." |
| Supra API 실패 | 증명 없으면 실행 불가 | 보류, 5분 넘으면 알림 | "외부 가격 확인이 안 돼 기다리는 중이에요." |
| 매도 손실이 한도 초과 | 되돌림 | 나눠 팔기 또는 회수만 | "나눠서 팔고 있어요(남은 양 0.12 WETH)." |
| 풀 유동성 급감 (10-10 사례) | - | 보류 | "풀에 유동성이 거의 없어 기다려요." |
| 에이전트 서버 중단 | - | 재시작 후 이어서 | 사용자가 "지금 단계 직접 실행"(소유자 실행)을 할 수 있다 |
| 키퍼 가스 부족 | - | 알림(운영자) | 같음 |
| 만료 | 실행 거부 | 실행 안 함 | "보호 기간이 끝났어요. 연장하거나 꺼내세요." |
| 가격이 회수선 아래로 갔다 바로 회복 | 가격 조건은 실행 시점에만 검사 | 루프 시점 가격 기준 | 실행됐다면 기록과 이유를 보여 준다 |
| 사용자가 NFT를 금고 밖에서 조작 | 금고가 소유하므로 불가 | - | - |

## 6. 3분 데모 순서

데모에서 실제 하락을 기다릴 수 없다. 그래서 팀 NFT의 **기준가를 현재가보다 높게 등록**해 첫 회수선이 이미 지나 있게 만든다. 발표에서 이 사실을 먼저 말한다.

| 시간 | 화면 | 핵심 문장 |
| --- | --- | --- |
| 0:00~0:30 | 문제: HSKSwap LP 17개 중 "들고 있기"보다 나은 것 0개, #14 −26% | "범위를 정한 LP는 하락장에서 손실이 커집니다." |
| 0:30~1:10 | 팀 WHSK LP 선택, 보호 설정, 미리보기(지키는 금액과 포기하는 금액, 비용 고지) | "보험입니다. 하락장에서 지키는 대신 평소에는 비용을 냅니다." |
| 1:10~1:50 | 맡기기 → 에이전트가 첫 단계 실행 → Blockscout 거래, 받은 USDT | "에이전트는 정해진 단계와 매도만 할 수 있고, 돈은 바로 사용자 지갑으로 갑니다." |
| 1:50~2:20 | 감시 화면: 외부 가격과의 차이, 보류 조건 시연(허용 차이를 0.1%로 낮춰 거부되는 장면) | "HSKSwap 가격이 외부와 어긋나면 팔지 않습니다." |
| 2:20~2:45 | 채팅 "왜 뺐어?", "예전에도 효과 있었어?" | 숫자와 출처, [모의] 표시 |
| 2:45~3:00 | 백테스트 요약과 한계, 메인넷 계약 주소, 공식 도구 목록 | "2018년 이후 하락장 248번 중 247번에서 손실을 줄였습니다. 평균 이득은 지금처럼 수수료가 낮을 때만입니다." |
