**Supra를 넣는 이유와 대안:** 가산점 때문이 아니라 얇은 풀에서 시세 조작을 막기 위해서다. 대안은 풀 자체의 시간가중평균가격(TWAP, 관측 240개)이다. TWAP은 외부 의존이 없지만, 풀 전체가 외부 시세와 어긋난 경우(빈 풀, 느린 차익거래)를 못 잡는다. Supra는 외부 API와 가스 약 36만이 추가된다. 판단: 오라클 검사는 넣되, Supra API가 일정 시간 실패하면 사용자가 정책에서 "TWAP 검사로 대체"를 고를 수 있게 하는 것은 후속 과제로 둔다. MVP에서는 증명이 없으면 실행하지 않는다(보수적).

**가산점 전략:** 쓰는 공식 요소는 모두 실제 기능을 맡는다(실행 경로, 가격 검증, 주소, 검증·추적). 공고에 이름이 있어도 제품과 맞지 않는 것(CCIP, HSP)은 넣지 않는다. 발표 자료에 이 표를 한 장으로 넣는다.

## 4. 아키텍처

```
[사용자 지갑] --서명--> [LPGuardVault (메인넷, 새로 작성)]
     |                       |  decreaseLiquidity / collect --> [HSKSwap NonfungiblePositionManager]
     |                       |  exactInputSingle             --> [HSKSwap SwapRouter02] --> [풀]
     |                       |  verifyOracleProofV2          --> [Supra Pull Oracle]
     |                       |  USDT·수수료 --> 사용자 지갑
     v                       ^
[웹 화면] <--REST--> [에이전트 서버] --executeStep(키퍼 키)--+
                        |  1분 루프: 풀 상태, 신호, 판단, 실행
                        |  Supra 증명 API (rpc-mainnet-dora-2.supra.com)
                        |  HSK RPC (eth_call, eth_getLogs), Blockscout API
                        |  LLM (설명, 채팅)
                        +  SQLite (판단 기록, 신호 캐시)
```

| 구성 | 기술 | 이유 |
| --- | --- | --- |
| 계약 | Solidity 0.8.24, Foundry | 메인넷 포크 시험(`--fork-url`)과 Blockscout 검증(`--verifier blockscout`)이 바로 된다. |
| 에이전트·백엔드 | Node 22, TypeScript, viem(또는 ethers v6), Fastify, SQLite | 계약 호출과 REST를 한 프로세스로 묶는다. 이번 조사에서 ethers v6으로 모든 호출을 확인했다. |
| 화면 | React(Vite) + wagmi + viem | 체인 177을 직접 정의해 지갑 연결 |
| 채팅 | LLM 함수 호출(도구 사용) | 숫자는 도구 결과만 쓰게 한다(`API-명세.md` 3절). |
| 백테스트 표 | 기존 `scripts/` 결과를 JSON으로 내보냄 | 화면에 [모의]로 표시 |

## 5. 외부 API 사용 메모 (직접 확인한 동작)

| API | 메모 |
| --- | --- |
| HSK RPC | `User-Agent` 헤더가 없으면 403을 준다. `eth_getLogs`는 5,000블록까지만 된다("block range too large"). 과거 블록 `eth_call`이 된다(포크 시험 가능). 로그에 `blockTimestamp`가 들어 있다. 블록 간격 약 2초. 11-25 가스 가격 500 gwei. |
| Supra 증명 | `POST https://rpc-mainnet-dora-2.supra.com/get_proof`, 본문 `{"pair_indexes":[1],"chain_type":"evm"}` → `proof_bytes`(16진수, 0x 없음). API 키 없이 됐다. 여러 쌍을 한 번에 받을 수 있다(`[517,1]`). 증명 검증 가스 약 36.5만. |
| Blockscout | `/api/v2/smart-contracts/{주소}`에서 ABI와 검증 정보. 요청 간격 1~2초 권장(429 대응). 계약 검증은 `forge verify-contract --verifier blockscout --verifier-url https://hsk.blockscout.com/api/` (HSK에서 실제 동작은 배포 날 확인). |
| QuoterV2 | `quoteExactInputSingle`은 view가 아니므로 `eth_call`(staticCall)로 부른다. |

**거래 비용:** 실행 한 번(증명 검증 + 회수 + 수령 + 매도)은 약 80만 가스로 추정한다. 500 gwei면 0.4 HSK, 약 0.03 USDT다.

## 6. 단위와 가격 규칙

- 두 풀 모두 token0이 위험자산(소수 18자리), token1이 USDT(소수 6자리)다.
- 사람이 읽는 가격 = (sqrtPriceX96 / 2^96)^2 × 10^(18−6).
- 계약 안 가격 비교는 1e18 고정소수점으로 맞춘다. Supra 값은 `decimal` 필드로 맞춘다.
- 회수선은 가격(선형) 기준이다. 화면이 sqrtPriceX96으로 바꿔 정책에 넣고, 계약은 감소 순서만 검사한다.
- 시간은 저장·전송 모두 UTC 초, 화면만 KST.

## 7. 보안 원칙

- 금고에 관리자·업그레이드·임의 송금 함수가 없다.
- 키퍼 개인 키는 서버 환경 변수에만 둔다. 저장소와 문서에 쓰지 않는다. 키퍼 지갑에는 가스용 HSK만 둔다.
- 사용자 자금이 움직이는 거래는 사용자가 지갑에서 서명한다(예치, 정책, 인출). 키퍼는 정책 범위의 실행만 한다.
- 메인넷 배포와 팀 자금 이동은 팀이 명시적으로 승인한 뒤에만 한다.
- 외부 입력(오라클 증명, 키퍼가 정한 매도량)은 계약이 다시 검사한다.
