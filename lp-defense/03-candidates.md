# 3. 후보 정리: 같은 방향 안에서 고를 수 있는 안

방향은 사용자가 정했다: **하락장에서 LP의 위험을 관리한다(하단 근처 분할 회수).**
아래 후보는 모두 이 방향 안에 있다. 각 후보를 인계문 2절 기준으로 **따로** 평가했고, 서로 다른 사용자의 사례를 한 사람의 흐름으로 합치지 않았다.

| --- | --- | --- | --- | --- | --- |
| **1. 집중 LP 하단 방어 에이전트** | 범위를 정해 공급하는 개인 LP | 없음 | 가장 선명 | **조건부 유지 (추천)** | 보류 |
| **2. 깊이를 지키는 부분 회수 에이전트** | 유동성을 깔아 두는 운영 주체 | 있음 (주소 2개) | 효과가 작게 보임 | 조건부 | 조건부 |
| 3. 회수·재공급 순환 에이전트 | 1과 같음 | 없음 | 복잡함 | 1의 확장으로만 | 보류 |
| 4. LP 진입 판단 도우미 | LP를 할지 고민하는 사람 | 확인 못 함 | 단순함 | 보류 | 보류 |
| 제외: 범위 주문으로 나눠 팔기 | | | | 제외 | |

## 후보 1. 집중 LP 하단 방어 에이전트 (원안 구체화)

**한 문장.** HSKSwap에 범위를 정해 유동성을 공급한 사람이 하락장에서 손실 꼬리를 자르려면, 하단에 가까워질 때 얼마를 빼고, 뺀 WHSK를 팔지 말지 정해야 한다. 지금은 화면을 계속 보다가 직접 빼거나 그냥 둔다. 그러면 하단 아래로 떨어지는 동안 USDT가 모두 WHSK로 바뀐다. 우리는 **회수를 계약 규칙으로 자동화하고, 처분 판단을 AI가 한도 안에서 하도록** 바꾼다.

| 기준 | 평가 |
| --- | --- |
| 사용자와 계기 | 이 체인에는 **없다**(집중 범위 시험 포지션만 있음). 다른 체인의 집중 LP와 자동 청산 도구 수요가 간접 근거다 |
| 페인포인트 깊이 | 실제 풀 가격 기준으로, ±10% 범위가 하단을 건드린 30일 구간의 평균 손실은 −15.9%, 최악은 −43.3%다(01 문서 3-6) |
| 가장 강한 대안 | ① 처음부터 사다리 범위 ② 다른 체인의 자동 청산 도구 ③ 직접 보기 |
| 대안 대비 남는 것 | 회수와 처분의 분리, TWAP 확인, 받는 주소 고정 가드, 이 체인 최초 |
| 기술의 역할 | 계약: 회수 규칙, 한도, 받는 주소. AI: 처분(매도·보유)과 재공급 제안. AI를 빼면 사람이 하락장에서 "지금 팔까"를 직접 정해야 한다 |
| 플랫폼 적합성 | 보통. HSKSwap V3 구조와 이 풀의 얇은 깊이(TWAP 필요성)를 쓴다. 이 체인만의 데이터가 선택을 크게 바꾸지는 않는다 |
| 사용자에게 돌아오는 것 | 하단을 건드린 구간에서 회수만으로 평균 +2.3%p, 33개 중 28개에서 나음. 처분까지 하면 급락에서 크게 지키지만 흔들림에서는 잃는다 |
| 메인넷 숫자 | 200~500달러 실포지션 + 좁은 범위 시연 포지션으로 실제 단계 회수 |
| **판정** | **해커톤: 조건부 유지.** 데모가 선명하고 공고 항목 5/6에 맞는다. **사업: 보류.** 사용자가 없고, LP 자체가 이 풀에서 기대 손익 마이너스다 |

## 후보 2. 깊이를 지키는 부분 회수 에이전트 (운영 주체용)

**한 문장.** 체인이나 프로젝트의 시장을 유지하려고 DEX에 유동성을 깔아 둔 운영 주체가 하락장이나 점검 때 노출을 줄이려면, 얼마를 빼고 얼마를 남길지 정해야 한다. 지금은 사람이 직접 전부 빼고 전부 다시 넣는다. 그 사이에는 시장이 죽는다(10/10 이후 5.9일 무거래). 우리는 **"남길 깊이"를 계약 조건으로 두고, 그 안에서 부분 회수와 나눠 재공급을 에이전트가 하도록** 바꾼다.

| 기준 | 평가 |
| --- | --- |
| 사용자와 계기 | **있다.** `0x8fed…95e`(WHSK/USDT 99.9987%), `0xb3e9…9b2`(WBTC·WETH). 10/10 세 풀 동시 전량 회수, 10/16·10/30 나눠 재공급(01 문서 3-3). **행동은 직접 확인했고, 목적은 확인하지 못했다** |
| 페인포인트 깊이 | 5.9일 무거래, 빈 풀에서 0.63달러로 가격 10% 변동. 10/16 이후 HODL 대비 −1,215달러, 수수료 +163달러. 운영 주체에게는 금액이 작다 |
| 가장 강한 대안 | 지금처럼 수작업. 간단한 스크립트. 마켓메이커에 맡기기 |
| 대안 대비 남는 것 | 깊이 하한을 계약이 지킴. 회수·재공급 기록이 체인에 남음(누가 왜 뺐는지). 다 빼지 않아도 노출을 줄일 수 있음 |
| 기술의 역할 | 계약: 깊이 하한 계산, 받는 주소 고정. AI: 회수를 이어 갈지 멈출지, 재공급 시점. 매도는 하지 않는다(02 문서 Q9) |
| 플랫폼 적합성 | **높다.** 이 체인의 실제 풀 구조(유동성이 사실상 한 주체에 있음)에서 나온 문제다 |
| 사용자에게 돌아오는 것 | 전 구간 포지션에서 분할 회수의 손실 감소는 평균 0.34%p로 작다. 가치는 손실보다 **"시장을 죽이지 않는 회수"**와 **운영 기록**이다 |
| 메인넷 숫자 | 우리 소액 전 구간 포지션으로 깊이 하한 계산과 부분 회수를 시연. 운영 주체 포지션은 건드릴 수 없다 |
| **판정** | **해커톤: 조건부.** 사용자 근거는 가장 강하다. 하지만 데모에서 보이는 효과가 작고 트레이딩 느낌이 약하다. **사업: 조건부.** 운영 주체가 이 문제를 느끼는지 한 번 확인하면 유지로 올라간다 |

## 후보 3. 회수·재공급 순환 에이전트 (후보 1의 확장)

**한 문장.** 후보 1에서 회수한 뒤 언제, 어느 범위로 다시 넣을지까지 AI가 맡는다.

- **근거:** 운영 주소도 나눠서 재공급했다(10/16에 절반, 10/30에 나머지 절반). 재공급 시점은 사람이 고민하는 실제 결정이다.
- **문제:** 판단 대상이 둘(처분, 재공급)로 늘어 검증이 어렵다. 재공급까지 넣은 모의 실험이 아직 없다. 범위를 자주 옮기면 손실이 확정된다.
- **판정:** 단독 후보로는 보류한다. 후보 1의 "재공급 제안(사용자 승인)" 기능으로만 넣는다.

## 후보 4. LP 진입 판단 도우미

**한 문장.** LP를 할지 고민하는 사람에게 이 풀의 실측 수수료와 손실을 보여 주고, 지금 들어갈지와 범위 폭을 제안한다.

- **근거:** 수수료가 손실의 13%라는 계산이 그대로 핵심 정보다.
- **문제:** 이 풀에서는 거의 항상 "하지 마라"가 답이다. 규칙으로 충분해서 AI의 역할이 약하다. 트레이딩 에이전트가 아니다.
- **판정:** 보류. 후보 1의 첫 화면(02 문서 Q2)으로 넣는다.

---

## 제외: 범위 주문으로 나눠 팔기

단일 자산 범위 포지션을 지정가 주문처럼 써서 HSK를 나눠 파는 방식이다. 이것은 **지난 주제(분할 매도)로 되돌아가는 것**이라 인계문 규칙 1에 따라 제외한다.

## 추천과 바꿀 조건

**추천: 후보 1 (+ 후보 3·4의 일부를 기능으로).**

1. 사용자가 정한 방향("하단 근처 분할 회수")은 하단이 있는 집중 범위 LP에서만 성립한다. 전 구간 포지션(후보 2)에서는 분할 회수의 효과가 평균 0.34%p로 너무 작아서, 방향의 핵심이 약해진다.
2. 해커톤 판단 기준은 완성도, 기술적 성숙도, 혁신성이다. 후보 1이 메인넷에서 가장 선명하게 작동을 보여 준다(하단, 단계 회수, 처분 판단, 손익 화면).
3. 약점(이 체인에 사용자가 없음)은 숨기지 않고 발표의 "왜 지금 이 체인에 집중 LP가 없는가 → 수수료 대비 위험 → 위험 쪽을 줄이는 도구" 흐름으로 쓴다. 다만 이 도구가 LP를 이익으로 바꾸지는 못한다는 것도 함께 말한다(02 문서 Q2).

**후보 2로 바꿀 조건.** 운영 주소(또는 HashKey 생태계 팀)에서 "일괄 회수·재공급이 번거롭다", "깊이를 남기며 줄이고 싶다"는 확인을 **한 번이라도** 받으면 후보 2가 더 강해진다. 사용자 근거가 실재하게 되기 때문이다. 서울 현장 행사나 HashFans 채널에서 물어볼 수 있다. 확인 없이 후보 2로 가면 "남의 행동을 추측한 제품"이 된다.

**두 후보는 같은 가드 계약을 쓴다.** 후보 1로 만들어도 깊이 하한 조건 하나를 더하면 후보 2가 된다. 이것은 구현상 공유일 뿐이고, 발표에서는 사용자를 하나로 정해 말한다.
