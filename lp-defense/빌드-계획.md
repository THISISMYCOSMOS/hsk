## 1. 구성 요소

표의 "공식" 열에서 HSKSwap은 Uniswap v3 포크인 HSKSwap 계약을, HashKey는 HashKey가 문서로 제공한 요소를 뜻한다.

| 구성 요소 | 하는 일 | 공식 요소 |
| --- | --- | --- |
| 자체 스마트컨트랙트(금고) | NFT 한 개를 맡고, 사용자가 정한 정책 안에서만 회수와 매도를 실행한다. | HSKSwap 포지션 관리자와 SwapRouter02를 호출한다. |
| 키퍼(실행 봇) | 체인을 감시하다가 조건이 맞으면 금고의 실행 함수를 호출한다. | HSK Chain RPC, HSKSwap 풀 |
| AI 판단 모듈 | `기획-정리.md` 4절의 규칙 네 가지를 따른다. 위험 신호가 있으면 회수를 앞당기고, 하단에서는 전부 뺄지 남길지 정하고, 회복 시 재공급을 제안하고, 이유를 설명한다. | 없음 |
| 매도 비용 계산기 | `받는 USDT = P·Δx(1−f) ÷ (1 + Δx(1−f)·√P / L)`로 매도 전 손실을 계산하고, 크면 더 잘게 나눈다. 실행 직전에는 Quoter로 다시 확인한다. | HSKSwap QuoterV2 |
| 채팅 | 계산이 끝난 숫자와 AI 판단을 받아 한국어로 설명한다. 허용된 행동만 고를 수 있다. | 없음 |
| 백테스트 화면 | LP 유지, 일정 비율, AI를 같은 가격 경로로 비교한 표를 보여 준다. 실측과 모의를 구분해 표시한다. | HSKSwap 실제 가격 |
| 데이터 소스 | 풀 상태, 스왑 이력, 포지션 정보, 보조 가격 | HashKey 토큰 문서의 주소, APRO HSK/USD 피드(하루 1회 갱신이라 보조 표시에만 쓴다) |

금고 계약이 가져야 할 함수는 다음과 같다. 팀 NFT 한 개를 받는 예치 함수, 원소유자와 처음 유동성(L0)을 기록하는 저장 로직, 사용자만 부르는 인출 함수(NFT와 잔액), 정책 등록과 수정과 중지 함수(소유자 전용), 키퍼가 부르는 실행 함수(회수, 수령, 매도를 한 거래로 묶음)다. 정책에는 허용 토큰과 풀, 회당 한도와 일일 한도, 최소 수령액, 만료, 재사용 방지 번호가 들어간다. 재공급 함수는 사용자 확인이 있을 때만 열린다.

키퍼가 할 수 있는 것은 정책 안의 실행 함수 호출뿐이다. 키퍼는 정책을 바꾸거나, 임의 주소로 송금하거나, NFT를 꺼낼 수 없다. 회수한 자금은 모두 원소유자에게 귀속된다. 이 권한 모델은 팀 원안 4절을 그대로 따른다. 건별 서명 모드와 사전 승인 모드 중 MVP에서 어느 쪽을 먼저 만들지는 팀이 정해야 한다. 이 계획은 정책을 한 번 등록하는 사전 승인 모드를 먼저 만드는 것으로 가정했다.

## 2. 포크 검증 체크리스트

특정 메인넷 블록을 고정한 로컬 포크에서 아래 순서대로 진행한다. 앞 단계가 통과해야 다음 단계로 간다.

1. 같은 블록에서 배포 코드, 세 계약의 `factory()` 일치, `getPool(WETH, USDT, 3000)`, 풀의 token0과 token1과 fee와 slot0과 liquidity를 읽는다. 가격 방향과 소수 자릿수도 맞춘다.
2. 팀 NFT 한 개의 `ownerOf`, `positions`, `getApproved`를 읽는다. 이어서 승인, 금고 예치, 원소유자와 L0 기록, 인출까지 돌려 본다.
3. `decreaseLiquidity`를 호출하고 반환된 원금 수량을 기록한다.
4. `collect`를 호출해 금고로 받는다. 이전에 쌓인 미수 수수료는 이번 원금과 분리해서 계산하고, 매도 대상은 이번 회수 원금만으로 한다.
5. SwapRouter02에 매도할 양만큼만 `approve`한다.
6. `exactInputSingle`을 `amountOutMinimum`을 넣어 호출하고, 실제 받은 USDT 잔액을 확인한다. 함수의 정확한 인자 형식은 HSKSwap 배포본의 ABI로 확인한다. 아직 확인하지 못했다.
7. 최소 수령액을 일부러 높게 잡아 스왑이 실패하게 만들고, 회수와 수령까지 전부 되돌아가는지 본다.
8. 내 LP를 뺀 직후에는 풀 깊이가 줄어든다. 회수 전 Quoter 견적과, 회수 후 실제 스왑 결과를 비교해 차이를 기록한다. 1,000 USDT ±10% 포지션은 풀 유동성의 약 20~25% 규모이므로 차이가 클 수 있다.
9. 실패 경로를 점검한다. 만료, 같은 실행 번호의 재사용, 승인 취소, 잔액 부족, 키퍼가 멈췄다가 재시작한 경우에 자금이 어디에 남는지 확인한다. 과거 상태를 주는 RPC가 없으면 확보한 블록만 증거로 쓴다.

## 4. 메인넷 배포

실제 서명, 배포, 자금 이동은 팀이 명시적으로 승인한 뒤에만 한다. 이 계획서를 쓴 작업에서는 아무것도 하지 않았다.

1. 포크 체크리스트를 모두 통과한 계약 코드를 동결한다(커밋 번호 기록).
2. 팀이 배포 지갑, 가스용 HSK 금액, 데모에 쓸 소액을 승인한다. 개인 키는 문서에 적지 않는다.
3. 체인 ID 177에 배포하고 Blockscout(hsk.blockscout.com)에서 소스를 검증한다. 검증 방식이 HSK Chain에서 어떻게 동작하는지는 아직 모른다.
4. 배포 직후 해당 주소에서 정책(허용 토큰, 풀, 한도, 소유자, 키퍼 주소)을 직접 읽어 기록한다.
5. 기록할 것은 세 가지다. 컨트랙트 주소와 배포 거래 해시, 검증된 소스 링크, 체인에서 읽은 정책 값이다. 이어서 팀 NFT 실거래의 거래 해시와 받은 금액도 남긴다.
6. 화면에는 포크 실행, 메인넷 읽기, 메인넷 배포, 메인넷 실거래를 각각 따로 표시한다.
