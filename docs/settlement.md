# 직접 정산 로컬 검증

금액별 메인넷 견적 조회는 이 컨트랙트의 배포나 서명 없이 실행된다. 아래 테스트는 체인 ID 31337의 로컬 EVM, 모의 토큰, 고정 견적을 사용한다. 메인넷 배포 주소, 트랜잭션 해시, 실제 가스 지출, 실현 절감액은 없다.

## 주문과 정산

`contracts/src/DirectSettlement.sol`의 두 주문은 한 쌍의 지정 토큰을 반대 방향으로 매도한다. 누구나 두 서명을 제출할 수 있고 각 토큰은 서명자 지갑에서 상대 서명자의 지갑으로 이동한다. 정산 비용을 별도로 인출하는 함수는 없다.

서명 도메인은 `HSK Smart Execution`, 버전 `1`, 체인 ID, 검증 컨트랙트 주소로 구성한다. Order 필드는 순서대로 maker, sellToken, sellAmount, minBuyAmount, minFill, costBufferPerFill, deadline, salt이며 정확한 타입은 소스의 ORDER_TYPEHASH에 있다. 수량은 각 토큰의 최소 단위 정수, deadline은 Unix 초다. salt는 주문 구분값이고 체결량과 취소 상태는 전체 주문 digest를 키로 저장한다. [EIP-712](https://eips.ethereum.org/EIPS/eip-712)

한 건의 `matchOrders` 호출에서 양측 서명, 기한, 잔여 매도량, 최소 체결량, 비례 최소 수령액을 확인한다. 양측 모두 동일 호출 시점의 `dex.amountOut(sellToken, sold)`에 수령 토큰 단위로 서명한 건당 비용 여유분을 더한 금액보다 많이 받아야 한다. 상대가 제시한 대금이 이 조건을 충족하지 못하면 두 주문 모두 보류된다. minFill을 sellAmount와 같게 지정하면 전량 체결만 허용한다. minFill보다 작은 잔량은 이후 체결되지 않으며 소유자가 취소할 수 있다.

컨트랙트는 양측 매도량을 기록한 뒤 네 지갑 잔액 변화와 ERC-20 전송 결과를 검사한다. 두 번째 전송이 실패하면 첫 번째 전송, 사용한 승인량, 체결량도 함께 원복된다. 별도 가스 정산은 없으며, 서명한 비용 여유분이 실제 운영비와 네트워크 비용을 보전하는지는 오프체인에서 확인해야 한다. [ERC-20](https://eips.ethereum.org/EIPS/eip-20)

## 테스트 재현

Foundry 1.10.0과 solc 0.8.26을 사용했다. solc가 로컬에 설치된 환경에서는 다음과 같이 재현한다.

```sh
cd contracts
forge test --offline
```

| 로컬 시험 | 확인한 결과 |
|---|---|
| 전량 및 두 번의 부분 체결, 잔여량 초과, 서명 변경 | 누적 한도와 원래 서명 한도 적용 |
| 주문 만료, 부분 체결 후 취소, 제삼자 취소 | 소유자·기한 규칙 적용 |
| 체인 또는 검증 컨트랙트 변경 | 기존 서명 거부 |
| 최솟값, 가격 한도, 실행 시점 견적 악화 또는 견적 없음 | 조건 미충족 거래 거부 |
| 승인 철회, 잔액 부족 | 양측 전송 및 주문 상태 원복 |

신규 14개 테스트가 통과했다. 기존 `backtests/HSK_A_Session1.zip`도 임시 디렉터리에 풀고 `HSK_A_Session1`에서 `forge test --offline`을 실행해 30개 테스트 통과를 재확인했다. 두 결과 모두 모의 데이터다. Foundry가 표시하는 test 함수 전체 gas에는 테스트 코드가 포함되므로 주문별 가스 산출에 쓰지 않는다.

## 기존 인계 자료와 호환 범위

기존 SessionSettlement는 WHSK 고정 수량, USDT 한도, 수취인 지정, executor, RFQ와 자금이 있는 FixedBook을 전제로 한다. 새 프로토타입은 SELL 입력 토큰 수량 고정, 양방향 실행 시점 견적, 사용자별 최소 체결량과 건당 비용 여유분을 적용한다. 기존 ABI·서명·경로 JSON을 직접 넣을 수 없다. FixtureToken은 기존 자료의 로컬 모의 토큰 구현을 재사용했다. 기존 테스트와 fixtures는 원본 압축 파일에 보존되어 있다.

## 아직 검증할 항목

- IDexQuote의 구현체는 테스트의 FixedQuote만 제공한다. 실제 풀과 동기화되는 읽기 전용 어댑터와 HSK 포크 상의 견적 일치성, 조작 가능한 현물 기준가에 대한 보호를 별도로 검증해야 한다.
- 직접 정산은 두 주문 한 쌍 단위다. 복수 주문 일괄 처리 및 DEX 잔여량 처리를 하나의 호출로 원자적으로 묶는 실행 경로는 미구현이다. 부분 체결 잔량은 주문에 남는다.
- 실제 EOA 지갑 연동 및 서명 수집, 컨트랙트 지갑(ERC-1271), WHSK·USDT 실토큰 호환성, 배포 비용과 L1·L2 수수료, 외부 보안 검토는 미검증이다. 주문 서명은 로컬 테스트에서만 생성한다.
