# 금액별 견적 조회

저장소 루트에서 Python 3로 실행한다. 한 요청의 금액들은 같은 블록과 같은 가상 주문 장부를 각각의 초기 상태로 사용한다. 각 행은 독립 시나리오다.

```sh
python3 -m hsk sell 10 100 1000
python3 -m hsk buy 1 10 100 --json
python3 -m hsk sell 10 100 1000 --block 30710916
python3 -m hsk '25 USDT로 WHSK 매수'
python3 -m hsk '10 WHSK 매도'
python3 -m hsk --archive
```

`sell`은 지출할 WHSK, `buy`는 지출할 USDT를 지정한다. 숫자는 화면에서 읽는 토큰 수량이다. 한국어 입력은 두 예시와 `매도 10 100`, `매수 1 10` 형식을 지원한다. 인수를 생략하면 표준 입력에서 한 줄을 읽는다. 고정 문법을 사용하며 모델 호출은 0건이다. `--archive`는 저장소의 보관 블록 30,592,078에서 재구성한 고정 사례 세 건을 읽는다.

`--block`은 과거 상태를 제공하는 메인넷 RPC에서 지정한 블록을 재조회한다. 블록을 생략하면 조회 시점의 블록으로 비교한다. 가상 주문과 양측 비용을 모두 지정하면 `minimum_tested_input`은 요청한 금액 중 양측의 예상 순절감이 양수인 최소 금액을 표시한다.

## 가상 주문과 비용 조건

아래 JSON을 `scenario.json`으로 저장하고 `python3 -m hsk sell 400 600 1000 --scenario scenario.json`을 실행한다. 예시 가격과 비용은 입력 형식을 보여주기 위해 정한 가정이다. 값은 모두 토큰의 최소 단위 정수다. WHSK는 소수 18자리, USDT는 6자리다.

```json
{
  "token_in": "WHSK",
  "orders": [
    {
      "id": "hypothetical-1",
      "offer": 48500000,
      "want": 600000000000000000000,
      "cost": 100000000000000000
    }
  ],
  "remainder": "dex",
  "costs": {"dex": 0, "direct": 10000, "hybrid": 20000, "per_order": 1000}
}
```

이 가상 상대방은 48.5 USDT를 제공하고 600 WHSK를 요구한다. 상대방 비용 가정 `cost`는 상대방이 받는 토큰(예시에서는 WHSK) 기준이다. `costs`는 요청자가 받는 토큰(예시에서는 USDT) 기준이다. `min_out`은 전량 기준 최소 수령량이고 `remainder`는 `dex` 또는 `hold`다. 부분 체결 시 엔진은 비례 한도를 적용한다. 고정 비용과 주문당 비용의 배분은 [경제성 엔진 설명](economics.md)에서 확인한다. 비용을 모르면 해당 비용 객체를 생략한다. 명시한 0은 비용 가정 0으로 처리한다.

결과는 기준 전량 DEX와 가상 경로 수령액, 매칭·DEX·잔여 수량, **실제 비교 가능한 체결량** 기준 DEX와의 차이를 표시한다. 가상 상대 주문이 없으면 DEX 또는 주문 유지가 후보가 된다. 비용 미입력 시 비용 반영 후 예상 절감액은 미측정으로 표시한다. `--json`에는 제외된 후보별 근거, 선택된 상대별 편익, 원 단위 정수, 시나리오와 블록 식별자가 포함된다. 모든 행의 실현 절감액은 미측정이다.

## 반복 관측

```sh
python3 -m hsk sell 100 500 --scenario scenario.json --watch 10 --json
```

10초마다 같은 파일과 블록을 확인해 블록 해시 또는 주문·비용 조건이 바뀌면 새 결과를 한 줄의 JSON으로 출력한다. Ctrl+C로 종료한다. 단발 조회 중 RPC 또는 시나리오 오류가 발생하면 오류 사유를 표준 오류로 출력하고 종료 코드 1을 반환한다. 감시 모드는 다음 주기에 다시 시도한다. 메인넷 관측에는 지갑·토큰 승인·거래 전송이 필요하지 않다.
