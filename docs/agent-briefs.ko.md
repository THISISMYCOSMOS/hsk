# HSK Smart Execution 개발 지시서

감독은 네 담당자의 인터페이스, 증거와 통합 결과를 인수한다. 각 담당자는 [프로젝트 원문](project-brief.ko.md)과 아래 자기 역할을 함께 읽고 작업한다. 이번 마일스톤은 **WHSK/USDT 주문 금액을 바꾸면서 HSK 메인넷의 같은 블록에서 DEX 견적과 직접 매칭 시나리오의 차이를 확인하는 것**이다. 팀장의 이번 지시가 원문 11절의 소액 실거래 단계보다 우선한다. 키 사용, 실지갑 서명, 승인, 배포 및 거래 전송은 이번 업무 밖이다.

## 1. 시장 데이터 에이전트

HashKey Chain 메인넷(chain ID 177)에서 HSKSwap V3의 토큰, 풀, factory, QuoterV2의 주소·단위·인터페이스를 확인하라. 기존 보관 자료는 주소 발견과 회귀 검산에 활용하라. 한 번의 금액 비교에 쓸 블록을 고정한 뒤 매수·매도 견적을 최소 단위 정수로 반환하라. 비교한 풀과 수수료 구간을 기록하라. 직접 풀과 기본 HSKSwap UI의 최적 경로는 범위가 다르다. RPC 장애, 다른 체인, 누락된 견적, 블록 교체 상황을 테스트하라. 조회 시각·블록 해시·대상 주소·입출력 단위와 재실행 명령을 경제성 담당에게 인계하라.

## 2. 주문 매칭·경제성 에이전트

시장 담당의 고정 블록을 입력으로 받아 전량 DEX, 전량 직접 매칭, 복수 반대 주문, 부분 매칭 후 잔량 DEX 또는 유지를 비교하라. 주문 한도와 정수 반올림을 보존하고 결과에 체결량·잔량·기준 수령액·후보 수령액을 반환하라. 미체결 잔량의 가치를 수익에 더하지 마라. 탐색 범위와 누락 가능한 조합을 명시하라.

순절감 추정은 동일 단위·동일 체결 수량에서 사용자별 비용을 비교하라. 상대 주문의 기원과 비용 가정(L1 데이터, L2 실행, 승인, 재검증, 실패·전환)을 표시하고 풀 수수료를 중복 차감하지 마라. 미측정 비용과 관측된 0을 구별하라. 운영자의 비용과 손익은 별도 항목이다. 양방향·금액 경계·비경제적 체결·반대 주문 부재를 시험하고 동적 최소 체결량의 계산 범위를 설명하라.

## 3. 정산·사용자 보호 에이전트

기존 로컬 Solidity 정산 자료와 인터페이스를 먼저 검토하라. EIP-712 도메인·거래 방향·수량·만료·취소·부분 체결·누적 사용량을 검사하고, 비용과 수령 한도를 위반한 주문을 거부하라. 로컬 EVM에서 독립적인 두 주문, 승인 철회, 잔액 부족, 블록 상태 변화, 원자적 롤백을 시험하라. 테스트용 서명과 자산은 로컬 테스트 안에서만 사용하라. 실제 재견적 또는 모의 어댑터 중 어떤 경로를 검증했는지, 현재 엔진과 어떤 주문 유형을 공유하는지 보고하라. 계약 주소와 거래 해시는 배포 전에는 공란으로 두라.

## 4. 실행 에이전트·사용자 인터페이스 담당

사용자가 한국어 또는 명령행에서 방향과 거래 금액을 입력하면 시장 조회와 경제성 엔진을 호출하는 실행 계획을 구성하라. 한 블록에 여러 금액을 비교하고 새 블록·주문 조건 변경 시 재평가하라. 반대 주문·비용은 명시적 시나리오로 입력하게 하라. 결과에는 기준 DEX 수령액, 매칭 경로, 잔량, 비용 전 차이, 비용 반영 후 예상 절감액과 선택 사유가 필요하다. RPC 조회가 실패하면 사용자에게 실패 원인을 표시하라. 보관 예시는 사용자가 명시적으로 선택하도록 하라. 자연어 처리 방식과 AI 호출 유무를 밝히고 사용자 조건을 자동 완화하지 마라.

## 인수 순서와 완료 판정

1. 시장 담당과 경제성 담당은 입력 방향을 고정하고 raw 정수와 블록 식별자를 합의한다. 예산 기준 매수(exact-in)와 목표 수량 매수(exact-out)를 바꾸어 읽지 않는다.
2. UI 담당은 양방향 다중 금액 요청, 주문이 없는 경우, 가상 주문이 있는 경우, 비용 누락과 조회 실패를 정상 진입점으로 재현한다.
3. 정산 담당은 테스트 수·실행 환경·실패 조건을 제출한다. 감독은 로컬 계약 테스트, 포크, 메인넷 읽기 결과를 각각 판정한다.
4. 각 담당자는 변경한 파일, 실행 명령, 관측 블록/시각 또는 테스트 입력, 통과·실패·미측정 결과를 제출한다. 외부 서비스 추천이나 과거 보고서의 통과 건수는 이번 실행 증거에 포함하지 않는다.
5. 감독은 모든 금액의 단위와 증거를 검산한 뒤 결과를 공개한다. 공개 RPC에서 현행 블록의 견적을 얻지 못한 경우 이번 실시간 검증은 보류한다. 서명된 반대 주문과 비용 증거가 없으면 조건부 시나리오만 보고한다.
