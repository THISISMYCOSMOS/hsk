# WHSK/USDT 금액별 경제성 검산

`hsk.economics.quote`는 지정 블록에서 입력 토큰을 정해진 수량만큼 지출하는 경우를 비교한다. WHSK 입력은 매도, USDT 입력은 매수다. 비교 기준은 연결한 HSKSwap V3 단일 풀의 exact-input 견적이다. 해당 시점의 전체 DEX 최적 경로는 미검증이다.

## 입력과 결과

```python
from hsk.economics import quote
from hsk.market import get_snapshot

snap = get_snapshot()
q = quote(snap, "WHSK", 100 * 10**18)
print(q["baseline_out"], q["candidate"]["net_saving"])
```

모든 금액은 Python 정수다. WHSK는 18자리, USDT는 6자리의 최소 단위를 사용한다. 반대 주문은 사용자가 명시한 가상 조건이다. 예를 들어 WHSK 매도자 관점에서 `{"id":"m1","offer":8000000,"want":100 * 10**18}`은 상대가 100 WHSK에 8 USDT를 제시하는 시나리오다. 사용자의 실제 주문이나 현재 시세를 뜻하지 않는다. `min_fill`은 메이커가 지급하는 토큰의 최소 수량이며, 기본값은 1이다. `min_fill=offer`로 메이커 전량 조건을 표현한다. `min_out`은 테이커의 전량 기준 최소 수령액이다. 잔량 유지에서는 체결 비율만큼 적용한다.

한 스냅샷에서 반대 주문 최대 다섯 개의 모든 부분집합을 탐색한다. 각 부분집합에서는 유리한 지정가부터 주문 한도 또는 입력 잔량까지 채운다. `remainder="dex"`는 나머지를 동일 풀에서 한 번에 견적하고, `"hold"`는 잔량을 유지한다. 후자는 동일한 **실제 비교 수량**의 DEX 견적과 비교한다. 더 나은 중간 체결량, 다른 풀, 순서에 따른 전체 시장 반응은 라이브 탐색 범위 밖이다. 입력 수량·서브셋·정렬 규칙이 정의한 후보 안에서 테이커 절감액이 가장 큰 경로를 선택한다. 비용 미입력 시 총절감 예상치로만 비교한다. 반대 주문이 없으면 직접 체결량은 0이다.

| 결과 | 단위 및 의미 |
| --- | --- |
| `baseline_out` | 전량을 단일 풀에서 처리하는 경우의 출력 토큰 |
| `candidate.out`, `candidate.benchmark_out` | 예상 수령액과 동일 체결량의 DEX 수령액 |
| `candidate.matched_in`, `dex_in`, `held_in` | 입력 토큰의 직접 체결량, DEX 처리량, 잔량 |
| `candidate.gross_saving` | 예상 수령액에서 동일 수량의 DEX 견적을 뺀 값. DEX 견적은 풀 수수료를 이미 반영 |
| `candidate.net_saving` | 총절감액 + 기준 경로 비용 하한 − 후보 경로 비용 상한. 비용 불명 시 null |
| `candidate.fills` | 메이커별 수량, 역방향 독립 DEX 견적, 메이커 관점의 예상 절감액. 메이커 절감액은 **테이커 입력 토큰** 단위 |
| `candidates` | 제외된 경로를 포함한 독립 비교와 제외 사유 |
| `operator_profit_usdt_raw` | 선택적으로 입력한 운영자 수입에서 운영비를 뺀 값. USDT 최소 단위 |
| `sequential_baseline_out`, `realized_saving` | 라이브 단일 견적의 순차 거래 결과 및 실현 절감액은 미측정 |

`costs={"dex":..., "direct":..., "hybrid":..., "per_order":...}`는 모두 **테이커 출력 토큰** 기준의 시나리오 입력이다. DEX 비용은 회피 가능한 비용의 하한, 직접·혼합 경로는 후보 비용의 상한, `per_order`는 상대 주문 한 건의 추가 비용이다. 기준 비용 하한을 모를 때는 0으로 가정할 수 있다. 후보의 L1/L2 가스, 승인, 경제성 재검증, 실패·대안 경로 및 서비스 비용을 포함한 상한을 정할 수 없다면 전체 `costs`를 생략한다. 임의의 0은 가정으로 기록된다. 주문별 `cost`는 메이커 비용의 상한이며 메이커 수령 토큰 단위다. 메이커에 대해서는 피할 수 있는 DEX 비용을 0으로 놓는다. `operator={"revenue_usdt":..., "cost_usdt":...}`는 운영자 수입/지출 가정만 계산한다. 발생하지 않은 영수증, RPC 비용 또는 AI 사용료를 생성하지 않는다.

양측의 체결별 독립 DEX 견적과 지정가를 검사한다. 양측 중 한쪽의 알려진 비교 절감액이 0 이하인 직접 매칭은 제외한다. 금액 비교만으로 서명, 잔액, 승인, 최신성, 온체인 체결을 보장할 수 없다. RPC 조회 실패는 계산 오류로 반환된다. 같은 방향·수량은 한 호출 안에서 캐시한다.

`minimum_economic_amount(snap, token_in, amounts, orders, costs=...)`는 양측 비용이 입력됐을 때 요청된 최대 64개의 **후보 금액**을 오름차순으로 검사한다. 양측 모두에 양의 추정 순절감액이 가능한 최초의 검사 금액과 그때의 직접 체결량을 반환한다. 비용이 없으면 `costs_unmeasured`다. 연속 구간의 임계량은 미확인이다.
